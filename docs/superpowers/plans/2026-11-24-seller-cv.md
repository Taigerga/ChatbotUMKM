# Seller CV — Asisten Katalog dari Foto Rak Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bangun fitur Penjual "Asisten Katalog dari Foto Rak": satu foto rak → banyak kotak deteksi → usulan produk → mapping kelas ke `productId` → riwayat scan, terisolasi per tenant.

**Architecture:** Service Python baru `cv/` (FastAPI + Ultralytics) dipisahkan dari `ml/` agar torch/ultralytics tidak menyentuh lima model existing. NestJS `/api/v1/cv/*` jadi proxy + penyimpan mapping/riwayat di MariaDB via Prisma. Next.js menambahkan halaman `/cv-katalog` yang meng-upload foto dan menampilkan usulan. Model yang dipakai `yolo26n` hasil training ulang dari PhantomStock yang sudah dibersihkan.

**Tech Stack:** Python 3.13, FastAPI, Ultralytics YOLO26, Pillow, pytest; NestJS 12, Prisma 7, MariaDB, Vitest; Next.js 16 App Router, React 19, Tailwind 4.

**Spec:** `docs/superpowers/specs/2026-11-24-seller-cv-design.md`

**Scope:** Penjual saja. CV Pembeli (visual product search) dapat spec + plan terpisah setelah plan ini selesai dan terverifikasi.

## Global Constraints

- `yolo26n.pt`, `imgsz=640`, `conf=0.25`.
- Upload gambar: JPEG/PNG/WEBP, maksimal 10 MB per file. Validasi server wajib.
- Semua endpoint CV di API: `JwtAuthGuard` + `TenantGuard`, header `x-tenant-id` wajib.
- Tidak ada auto-update stok/harga/SKU. Output teks harus menyebut "box terdeteksi", bukan "stok".
- Tidak mengubah file di `ml/` dan tidak menambah dependency ke `ml/requirements.txt`.
- Tidak menyimpan bytes gambar. Riwayat menyimpan metadata + deteksi saja.
- Kamera memakai `<input type="file" accept="image/*" capture="environment">` (hint); upload tetap jalan di desktop.
- Sebelum mengubah kode Next.js, baca guide relevan di `node_modules/next/dist/docs/` sesuai `apps/web/AGENTS.md`.

## Review Focus

1. Upload >10 MB → 413 dari `FileInterceptor`; tipe bukan gambar → 400 `INVALID_IMAGE`. CV service tidak dipanggil. Test: Task 7 step 2.
2. Dua tenant memetakan `classId` yang sama ke produk berbeda → mapping tidak bocor. Test: Task 7 step 6.
3. Deteksi nol box → response valid, UI empty state, bukan error. Test: Task 3 step 4.
4. CV service mati → API balas 503 dengan kode `CV_UNAVAILABLE`, web tampilkan pesan, tidak crash. Test: Task 7 step 7.
5. Confidence rendah pada kelas langka → tetap tampil sebagai usulan, tidak otomatis terpetakan. Test: Task 9 step 4.
